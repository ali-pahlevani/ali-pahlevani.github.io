About

I'm a robotics software engineer who specializes in SLAM, sensor fusion, autonomous navigation and motion planning.

Most of my days are spent in ROS 2 with C++ and Python, fusing 2D and 3D LiDAR, cameras, IMUs and wheel odometry into localization that holds up in the real world, not just in simulation. I've deployed SLAM and Nav2 on real robots, from autonomous forklifts to indoor and outdoor mobile platforms, tuned LiDAR–IMU odometry for ADAS research, and built the simulation worlds that let teams test all of it before a robot ever moves.

My background is in aerospace: an M.Sc. in flight dynamics and control from Sharif University of Technology, where I graduated first in my class. I work with companies, research groups and startups as a freelancer, and I teach SLAM and modern C++ to other robotics engineers.

Mobile Robot URDF Maker

A complete description-to-simulation pipeline. A nine-step wizard takes you from chassis to controller to sensors, then simulates and drives the robot in Gazebo Harmonic, with no hand-written XML. One codebase serves ROS 2 Humble and Jazzy, adapting at runtime to whichever you sourced.

What v4 adds
  • Six ros2_control controllers (differential, skid-steer, mecanum, tricycle, tricycle-steering, Ackermann), with only the valid ones offered per chassis.
  • Dynamic multi-sensor system: any number of lidars and cameras, live in the 3D preview and auto-bridged to ROS 2.
  • Controller tuner with physics-based auto-suggest limits written straight into the controller YAML.
  • Hardware-interface selection: Gazebo, mock hardware, or a custom plugin.
  • Built-in teleoperation by D-pad or keyboard, backed by a cmd_vel_relay node.
  • Presets and sessions snapshotting the entire wizard state, including manual URDF edits.

Dynamic World Generator

2D Scan Merger

A ROS 2 composable node that merges any number of 2D LiDAR scans into one LaserScan. Existing solutions were capped at a fixed number of inputs by message_filters template constraints; that limit is gone.

How it works
  • Unlimited inputs via a custom approximate-time synchronizer with two-pass safety, so partial match failures never drop data silently.
  • Parallel ray projection using a persistent thread pool and C++20 std::barrier, with threads created once at startup.
  • No intermediate point cloud: rays go from polar coordinates straight to angular bins, with no PointCloud2 conversion and no PCL dependency.
  • Per-topic QoS, height filtering, and cached TF lookups for static mounts.
  • Integration test suite spinning the real node against synthetic scans and static TF.

Tested on Humble, compatible with Iron, Jazzy and Kilted Kaiju without code changes. Installable via apt for Humble, with Jazzy following.

  • C++20
  • ROS 2
  • Released on the ROS index

MAGI: Unitree Go2W In development

A full ROS 2 Humble and Gazebo Harmonic simulation of the Unitree Go2W, a wheeled quadruped with 16 actuated joints, driving across the Rubicon terrain. Every claim is measured against Gazebo ground truth rather than assumed.

The stacks, and what they bought
  • Description and sensors: Livox MID-360 lidar, wide-angle camera, 6-axis IMU and four foot force sensors, validated against datasheets.
  • Control: ros2_control with torque-controlled legs, gains sized from lever geometry; load spread across legs improved from 201x to 10.2x.
  • Stability: a command governor in the /cmd_vel path projecting twists onto a force-angle stability margin; upright runs went from 4/12 to 21/22.
  • State estimation: an EKF fusing IMU and wheel velocity cut yaw error from 67% to 5%, and leg odometry fixed the unstable vertical channel, from 108 m of drift to 1 cm.
  • 3D SLAM: RTAB-Map consuming the filtered odometry and publishing only map to odom, cutting position error roughly tenfold.

RainBot: Mobile Manipulator

A mobile cobot pairing a Clearpath Husky A200 base with a Franka Emika FR3 arm, so it can navigate an entire site and manipulate objects wherever they are, rather than only within reach of a fixed pedestal.

The mission, end to end
  • Navigate to the table with Nav2 on a saved map, localized by AMCL.
  • Approach via a front-camera colour visual servo driving the base to the grasp point.
  • Grasp with verification read from the finger joint position before anything else happens.
  • Carry in a compact tucked pose, using a Gazebo DetachableJoint weld, since friction alone lost the box on every carry.
  • Place and verify, so failed placements are reported failed rather than silently assumed good.

Readiness-gated startup cut time-to-mission from about 115 s to 13–18 s, and the full stack runs at real-time factor 1.0.

Map Enhancer Wizard

Maps coming out of SLAM are rarely clean enough for reliable relocalization and path planning: walls drift, corners round off, noise accumulates. This GUI loads, filters and optimizes 2D occupancy grids in real time.

The workflow
  • Load standard .yaml and .pgm pairs.
  • Filter with erosion, dilation and Gaussian blur at adjustable kernels.
  • Optimize using user-placed control points and constraint pairs, tuned through gradient step, line weight, elastic weight and neighbour radius.
  • Anchor corners automatically, preserving structural geometry during optimization.
  • Work interactively with pan, zoom, live preview, snapshot history and undo, then export back to .yaml and .pgm.

Automation, AI-powered enhancement and 3D map support are on the roadmap.

  • OpenCV
  • Tkinter
  • Occupancy grids

GenZ-ICP, optimized

CPU-side optimization of the robust LiDAR odometry method from IEEE RA-L 2025, cutting total runtime by 20–50% depending on voxel resolution and cloud size, which is what makes it usable for real-time SLAM.

The optimizations
  • Vectorized TransformPoints using Eigen matrix operations instead of per-point loops.
  • Kernel value precomputation to avoid redundant multiplications.
  • Weight function simplification, cutting multiplications in the cost function.
  • Squared distance comparisons with squaredNorm() in nearest-neighbour search, minimizing sqrt calls.
  • Precomputed statistics for O(1) feature queries instead of O(P) lookups.
  • Iterator-based point cloud updates and safe removals for large voxel maps.

POA, the Pandemic Optimization Algorithm Sharif University of Technology

A metaheuristic for single-objective optimization that models how a pandemic spreads. Unlike most metaheuristics, which hold population constant, POA grows and shrinks its population the way an outbreak rises and falls, creating and killing individuals as it goes. Given careful parameter tuning it reaches near-optimal solutions in reasonable time.
